## 4. 完整知识清单与公式

### 4.1 供电、复位与 PVD

- [ ] 区分 VDD 数字电源、VDDA 模拟电源、VBAT 后备域与内部 1.8 V 核心供电区域；理解不同低功耗模式切断的区域不同。
- [ ] 上电复位/掉电复位（POR/PDR）保证电压未稳定时保持复位；复位释放与电源阈值/迟滞相关。
- [ ] PVD 是可编程电压监测器，监测 VDD 穿越所选阈值；典型阈值档约 2.2～2.9 V，最终以数据手册该器件最小/典型/最大值为准。
- [ ] PVD 输出连接 EXTI16，可选上升/下降沿产生事件或中断；中断中只记录状态/执行最小紧急动作，耗时保存应评估剩余电量。
- [ ] 分清 PVD“预警”和 PDR“硬复位”；不能假设 PVD 触发后还有无限时间写 Flash。
- [ ] 会读取并清理 PWR_CSR 的唤醒/待机标志和 RCC_CSR 的复位来源，避免旧标志导致误判。

### 4.2 WFI/WFE 与模式选择位

- [ ] `WFI`（Wait For Interrupt）等待可由 NVIC 响应的中断；`WFE`（Wait For Event）等待事件，理解 event register 与 `SEV` 的关系。
- [ ] `SCB->SCR.SLEEPDEEP=0` 进入睡眠；`=1` 选择深度睡眠，再由 `PWR_CR.PDDS` 区分停止/待机。
- [ ] 睡眠下 `SLEEPONEXIT=0` 为执行 WFI/WFE 立即睡；`=1` 可在最低优先级 ISR 退出后直接回睡，适合事件驱动但可能“主循环不再运行”。
- [ ] 停止模式 `PDDS=0`；`LPDS=0` 调压器开启、唤醒快，`LPDS=1` 调压器低功耗、功耗更低但唤醒延迟增加。
- [ ] 待机模式 `PDDS=1`；SPL 的 `PWR_EnterSTOPMode(...)`、`PWR_EnterSTANDBYMode()` 会设置关键位，但调用前仍需正确开 PWR 时钟、清标志、配置唤醒源。

### 4.3 三种低功耗模式

| 项目 | 睡眠 Sleep | 停止 Stop | 待机 Standby |
|---|---|---|---|
| CPU/时钟 | CPU 停，外设时钟可继续 | 1.8 V 域时钟停，PLL/HSI/HSE 关闭 | 1.8 V 域断电，PLL/HSI/HSE 关闭 |
| SRAM/普通寄存器 | 保留 | 保留 | 丢失 |
| BKP/RTC | 保留 | 保留 | 由后备域保持 |
| I/O | 保持运行模式状态 | 保持运行模式状态 | 变高阻态（浮空输入） |
| 唤醒后执行 | 从 WFI/WFE 后继续 | 从 WFI/WFE 后继续 | 相当于复位，从头执行 |
| 典型唤醒 | NVIC 中断 / 事件 | EXTI 中断 / 事件 | PA0-WKUP 上升沿、RTC 闹钟、NRST、IWDG |
| 关键恢复 | 通常无需重配系统时钟 | 醒来先为 HSI，必须恢复目标时钟 | 重走启动文件与初始化 |

- [ ] 睡眠 WFI 可被任意 NVIC 响应的中断唤醒；WFE 可被唤醒事件唤醒，I/O 保持。
- [ ] 停止模式的 EXTI 线必须在进入前配置；唤醒后 HSI 自动成为 SYSCLK，教程调用 `SystemInit()` 恢复 72 MHz。
- [ ] `SystemInit()` 的职责、超时和失败策略要理解；生产代码还应重新确认 `SystemCoreClock`，并恢复依赖时钟的 USART、TIM、SysTick 等时基。
- [ ] 待机唤醒不会从 `PWR_EnterSTANDBYMode()` 下一句继续；必须通过待机/唤醒标志与 BKP/RTC 恢复上下文。
- [ ] PA0-WKUP 是上升沿；进入前清 WUF，避免残留标志/高电平导致立即唤醒。RTC ALR 也需正确清标志。
- [ ] 待机时普通 SRAM 状态不能作为持久化依据；低频配置写内部 Flash，时间/少量状态放后备域。

### 4.4 修改主频的连锁影响

- [ ] 能从 HSE、PLL 倍频、AHB/APB 分频画出 SYSCLK/HCLK/PCLK1/PCLK2；STM32F103C8T6 常用 HSE 8 MHz ×9 = 72 MHz。
- [ ] 时钟公式：`f_SYSCLK=f_HSE×PLL_MUL`，`f_HCLK=f_SYSCLK/AHB_PRE`，`f_PCLKx=f_HCLK/APBx_PRE`；当 APB 预分频为 1 时 `f_TIMx=f_PCLKx`，否则 `f_TIMx=2×f_PCLKx`。
- [ ] 功耗记录统一使用 `P=V×I`、`E=P×t`；用电池容量粗估续航时须标明稳压损耗、占空比和器件静态电流，不能只用 CPU 模式电流代替整板电流。
- [ ] 修改 `system_stm32f10x.c` 后调用 `SystemCoreClockUpdate()` 或确保 `SystemCoreClock` 正确；不能只改显示变量。
- [ ] SysTick/软件 Delay、USART BRR、TIM PSC/ARR、ADC 时钟均依赖时钟树；主频变更后必须重算或重新初始化。
- [ ] APB 预分频不为 1 时，定时器内核时钟通常为对应 PCLK 的 2 倍；不能直接把 PCLK 当 TIMxCLK。
- [ ] Flash 等待周期与预取需匹配高主频；时钟切换要等待就绪并提供失败路径。

## 6. 闭卷编码与实物实验

### 6.1 闭卷任务

1. 从 SPL V3.5.0 工程实现 `Power_EnterSleep()`、`Power_EnterStop()`、`Power_EnterStandby()`，每个函数明确前置条件、清标志、唤醒源、返回后恢复动作。
2. 设计一张“需求 → 模式”的决策表：是否保留 SRAM、最大唤醒延迟、允许唤醒源、外设是否需继续、是否接受从头启动。
3. 用 `volatile` 标志在 USART/EXTI ISR 与主循环间传递事件；ISR 禁止 OLED 刷屏、Delay、Flash 写入或永久等待。
4. 给停止模式加入 `SystemInit()` 后的时钟自检：读取 `SystemCoreClock` 并通过 USART/TIM 实测确认，而非只信变量。

### 6.2 实物对照矩阵

| 模式 | 进入证据 | 唤醒动作 | 必须证明 |
|---|---|---|---|
| Sleep | 主循环进入 WFI 前打印序号 | USART1 收到一个字节 | 从下一句继续、数据回传、SRAM 计数保持 |
| Stop | 进入前记录 SystemCoreClock/计数 | PB14 下降沿 | EXTI 计数保持；唤醒后恢复 72 MHz，串口/Delay 仍正确 |
| Standby-WKUP | BKP 保存 boot_count 后进入 | PA0 上升沿 | 程序从头启动、普通 SRAM 丢失、BKP/RTC 保持 |
| Standby-RTC | 设置 `ALR=CNT+10` 后进入 | RTC 闹钟 | 约 10 秒后重启，并能读取唤醒/闹钟来源 |

可用电流表时分别记录运行、Sleep、Stop、Standby 的稳定电流与测量方法；不可用时写 `BLOCKED: 缺少电流测量仪器`，不得编造数值。

### 6.3 故障注入（至少三项）

- 停止唤醒后故意不恢复系统时钟，观察串口波特率/Delay/定时器异常，并定位到 SYSCLK 为 HSI。
- 漏开 APB1 PWR 时钟，记录 STOP/STANDBY 行为与寄存器读回。
- 进入待机前不清 WUF 或让 PA0 保持高电平，验证立即唤醒问题。
- 把 PB14 EXTI 边沿配置反，结合静态电平和波形定位“无法唤醒”。
- 错把待机当函数返回，故意在调用后安排状态更新，证明该代码不可达。
- 设置 `SLEEPONEXIT=1` 后观察主循环不再执行，解释中断退出即回睡。
