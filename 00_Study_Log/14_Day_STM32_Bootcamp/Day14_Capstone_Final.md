## 5. 综合项目规格：多源数据采集与安全日志终端

### 5.1 固定引脚与外设分配

| 子系统 | 外设/引脚 | 模式与约束 |
|---|---|---|
| 调度 | TIM2，无外部引脚 | 1 kHz 更新中断，只递增毫秒 tick/置到期标志 |
| 模拟采集 | ADC1 CH0/CH1：PA0/PA1 | 扫描 + DMA1 循环，缓冲区宽度必须为 16 位 |

| OLED | PB8 SCL、PB9 SDA | 教程软件 I2C；主循环低频刷新 |
| W25Q64 | SPI1：PA5 SCK、PA6 MISO、PA7 MOSI、PA4 CS | 模式 0，CS 推挽；处理 WREN/BUSY/页边界/扇区 |
| USART | USART1：PA9 TX、PA10 RX | 115200-8-N-1，RXNE ISR 写环形缓冲区 |

### 5.2 模块接口与数据流

实现以下等价接口；名称可不同，但职责、返回值和错误传播不可缺失：

```c
typedef enum { APP_OK=0, APP_EINVAL, APP_ETIMEOUT, APP_EIO, APP_ECRC, APP_EFULL } AppStatus;

AppStatus Sensor_Init(void);
AppStatus Sensor_ReadLatest(SensorSample *out);       /* 不永久阻塞 */
AppStatus Log_Init(void);
AppStatus Log_Append(const LogRecord *record);        /* 跨页拆分、写后校验 */
AppStatus Log_Read(uint32_t seq, LogRecord *out);
AppStatus Config_Load(AppConfig *out);                /* 版本/长度/CRC */
AppStatus Config_Save(const AppConfig *cfg);          /* 仅 SAVE 或显式变更 */
void       Protocol_Poll(void);                        /* 从环形缓冲区取字节 */
void       Scheduler_RunDueTasks(uint32_t now_ms);
```

数据流：ADC1→DMA 循环缓冲区→主循环快照/平均；I2C1→MPU6050 原始六轴；RTC→UTC；三者组装记录→SPI1/W25Q64。OLED 与 USART 只消费快照，不直接拥有传感器驱动。错误通过状态码和 `status_flags` 上报，不能被吞掉。

### 5.3 调度与并发契约

- TIM2 1 ms ISR：只更新 `volatile uint32_t g_tick_ms` 和必要到期位，不调用 I2C/SPI/OLED/printf/Flash。
- USART1 RXNE ISR：只把字节放入 256 字节无锁单生产者/单消费者环形缓冲区；满时置 overflow 并丢弃当前帧。
- EXTI ISR：清挂起位、保存按键事件；主循环以 20 ms 消抖并切换页面/记录状态。
- 主循环周期：协议每圈；按键 10 ms；MPU 20 ms（50 Hz）；ADC 快照 100 ms；OLED 200 ms；状态 1000 ms；日志默认 1000 ms，可配置 100～60000 ms。
- 所有周期判断使用无符号差值，允许 `uint32_t` tick 回绕；任务不得用长 Delay。
- IWDG 目标约 2 s，实际参数按 LSI 容差计算；每个 1 s 健康窗只有在协议、传感器、调度、存储状态机均取得进展时才喂狗。
- 没有到期任务且 RX 缓冲为空时，临界区内二次检查待办后执行 `__WFI()`，避免检查与睡眠之间丢失唤醒。

### 5.4 串口命令协议

帧统一为 ASCII `@<BODY>\r\n`，最大 96 字节，帧间超时 200 ms；超长、非法字符、参数越界或超时均丢弃到下一 `@` 并返回错误，解析器不得卡死。

| 命令 | 行为 | 成功响应 |
|---|---|---|
| `@START\r\n` | 开始记录；已开始时幂等 | `@OK,START\r\n` |
| `@STOP\r\n` | 停止记录；已停止时幂等 | `@OK,STOP\r\n` |
| `@STATUS\r\n` | 返回 seq、UTC、周期、传感器/存储/记录状态 | `@STATUS,<seq>,<utc>,<period>,<flags>\r\n` |
| `@SET,PERIOD,<100..60000>\r\n` | 仅改 RAM 中日志周期 | `@OK,PERIOD,<value>\r\n` |
| `@SET,THRESH,<0|1>,<0..4095>\r\n` | 设置 ADC 通道阈值 | `@OK,THRESH,<ch>,<value>\r\n` |
| `@TIME,<0..4294967295>\r\n` | 设置 RTC 的 UTC 时间戳 | `@OK,TIME,<utc>\r\n` |
| `@PAGE,<0..2>\r\n` | 选择 OLED 页面 | `@OK,PAGE,<page>\r\n` |
| `@SAVE\r\n` | 将当前配置写内部 Flash，成功回读后确认 | `@OK,SAVE\r\n` |

错误统一为 `@ERR,<CODE>,<DETAIL>\r\n`，CODE 至少含 `FORMAT`、`RANGE`、`TIMEOUT`、`BUSY`、`SENSOR`、`STORAGE`。禁止用 `atoi` 后不验证尾字符/溢出。

### 5.5 W25Q64 记录与内部 Flash 配置

W25Q64 每条记录固定 44 字节，按小端逐字段序列化，禁止直接把带填充的 C 结构体强转写入：

| 偏移 | 字段 | 类型/含义 |
|---:|---|---|
| 0 | magic | u32，`0x31474F4C`（LOG1） |
| 4 | version / length | u16=1 / u16=44 |
| 8 | sequence | u32，单调递增 |
| 12 | unix_utc | u32 |
| 16 | uptime_ms | u32 |
| 20 | adc0 / adc1 | 各 u16 |
| 24 | accel xyz | 3×i16，MPU6050 原始值 |
| 30 | gyro xyz | 3×i16，MPU6050 原始值 |
| 36 | status_flags / reserved | u16 / u16 |
| 40 | crc32 | u32，覆盖偏移 0～39 |

- W25Q64 `0x000000～0x000FFF` 保留元数据，日志从 `0x001000` 开始顺序写；写函数必须拆分所有 256 字节页边界。
- 擦除前确认 4 KB 扇区、WEL 与 BUSY；所有 BUSY 等待有超时；只有 CRC 回读成功才推进 sequence/指针。
- 内部 Flash 配置包含 magic、schema version、length、generation、period、两个阈值、时区显示偏移、CRC；只响应 `SAVE` 或明确低频事件，不随每条记录擦写。
- 指针/序号至少每 64 条或 STOP 时做低频检查点；启动时从检查点向前扫描 CRC，找到最后一条有效记录。断电不能把未完成记录标为有效。

### 5.6 OLED 页面

- Page0：UTC/本地时间、记录状态、sequence。
- Page1：ADC0/ADC1 与阈值告警。
- Page2：MPU6050 accel/gyro 摘要、sensor/storage/error flags。
- 刷新最多 5 Hz；只显示内存快照，禁止在 OLED 驱动内读取传感器或存储。

## 6. 综合项目验收场景

### 6.1 构建与资源

- 新构建必须 `0 Error / 0 Warning`。
- `.map` 必须证明 Flash <64 KB、SRAM <20 KB，并记录绝对字节；建议保留至少 4 KB Flash 与 2 KB SRAM。低于建议余量必须说明最坏栈/缓冲分析，否则硬门槛失败。
- `.map` 证明 `0x0800FC00～0x0800FFFF` 未被链接内容占用后，才允许内部 Flash 配置页；否则向前选择完整空闲页并同步修改文档/链接约束。
- 栈上禁止大数组，USART/ADC/协议/记录缓冲区大小与最坏使用量可解释。

### 6.2 必做故障与恢复

| 场景 | 注入 | 必须行为 |
|---|---|---|
| 非法串口包 | 超长、缺 CRLF、未知命令、负数/溢出、半包超时 | 返回/记录对应 ERR，丢弃坏帧，下一合法帧仍可解析 |
| MPU6050 断开 | 运行中拔除 SDA/SCL 模块连接 | I2C 超时退出，置 SENSOR flag，OLED/串口可用，恢复连接后可重新初始化 |
| W25Q64 BUSY/写保护 | WP 拉低或受控模拟 BUSY 超时 | 不永久等待、不推进 seq，返回 STORAGE/BUSY，解除后恢复 |
| 主循环卡死 | 受控调试开关阻塞超过 IWDG 上界 | IWDG 复位；启动报告复位来源和累计次数 |
| 配置断电恢复 | SAVE 成功后断电；另测保存中断/CRC 损坏 | 成功配置恢复；损坏配置被拒绝并使用安全默认值 |
| RTC/VBAT | 主电断开后恢复 | 有 VBAT 时 UTC 连续；缺证据则 NOT_PROVEN |

### 6.3 30 分钟稳定性

- 默认 1 秒一条，连续记录 30 分钟，期望 1800 条；允许启动边界 1798～1802 条。
- 全部记录 sequence 严格递增、UTC 不倒退、CRC 全通过；没有意外 IWDG/HardFault/复位、环形缓冲溢出或任务停滞。
- 每 5 分钟保存一次 STATUS，共至少 7 个时间点（含开始/结束）；随机回读至少 20 条并与运行日志交叉。
- 稳定性测试期间不得手动喂狗或暂停调试器；任何意外复位都需重计完整 30 分钟。
